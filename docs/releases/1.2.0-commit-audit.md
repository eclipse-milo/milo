# Milo 1.2.0 commit audit

## Review boundary and coverage

Last updated: 2026-09-30. Companion: [Milo 1.2.0 feature and migration guide](1.2.0.md).

The guide addresses upgrades from 1.1.7, the latest 1.1.x release, to 1.2.0. It excludes
anything already in 1.1.7, and it covers only significant new features and changes that may
require code changes in an application. Bug fixes and behavior changes that need no code change
are recorded here but have no guide entry. This audit keeps v1.1.7 as its exact comparison baseline so the
history range and sample verification remain reproducible.

The inventory comes from:

```sh
git rev-list --reverse --topo-order 85be7e7fce6d1d5896d7e0d15f6325b08577c087..43c6f21a2bd2cd8b259b25709f4fa921cd921c68
```

The audit has had two passes. The first (2026-09-04) compared v1.1.6 with
`b8377ea03e5ae3fe99de35487657db6bcd97bf1d` and assigned rows 001 through 140. The second
(2026-09-30) moved the baseline to v1.1.7 and extended the range to the current tip. Of the
first-pass commits, 85 are ancestors of v1.1.7 and left the range; their rows were removed, and
the remaining 55 keep their original numbers so cross-references stay valid. Gaps in 001-140
mark removed rows. Of the 241 commits after `b8377ea03`, 41 are ancestors of v1.1.7; the other
200 are rows 141 through 340.

Each non-merge diff was inspected against its parent. Each merge was inspected against
both parents, with `git show --remerge-diff` used to isolate conflict-resolution changes.
Changed public contracts, implementation paths, tests, examples, and configuration were
then reconciled against both the v1.1.7 baseline and the pinned final source. Existing feature
and architecture documents supplied context; they did not replace commit inspection.

Large additions were reviewed by API, data flow, implementation sections, and relevant
test assertions. The generated GDS commit was inspected across all 76 changed paths;
repetitive model wrappers and NodeId constants received pattern review. This is a migration
review, not independent certification of every generated constant or cryptographic operation.

The table records one row per commit. Hash labels are abbreviated for readability; each
link contains the full object ID. Classifications can overlap. A linked guide section covers
the feature or code change the commit contributes to; the disposition describes what the commit
changed, including behavior the guide leaves out. Test-only commits do not become separate shipped features.

## Baseline, merge, and supersession reconciliation

- v1.1.7 contains the Publish and subscription hardening, SessionFsm hardening, lazy
  DataTypeTree hardening, binary serialization optimizations, `UShort` caching, KeyStore
  atomic writes and watching, `TrustListManager` closability, client operation-limit recovery,
  event filter validation, Matrix and hashing fixes, and content-based trust-list removal. The
  guide sections that described these as 1.2.0 changes were removed or trimmed.
- Several commits in range carry changes already in v1.1.7 under another hash. They remain rows
  with no guide entry: `53a34760d` (backported as `10a59c857`), `caf4baf10` (`d7d5bdea9`),
  `c4d5251a7` (patch-equivalent to `cfe4dde4a`), `42cf5217f`, `d645c9d96`, and `003ecbe53`
  (patch-equivalent to `57e764cdd`, `982afe133`, and `5ebefc3c6`), `61421cd7d`, `538b1b50b`,
  and `b6fff1e09` (ported as `9def168e6`, `4df8e6159`, and `00fcf621e`), and `39f6940d0`
  (ported as `677dfdc83`). `d090e4b32` from the same event-filter pull request is 1.2.0-only.
  These equivalents were found with `git patch-id --stable` or by comparing production diffs.
- Merges with explicit resolutions: `91a886c84` combines mainline recovery hardening with ECC
  nonce, identity, and header work; `c19e4e3ec` retains the integration endpoint and token-policy
  implementation; `9709f4eab` combines KeyStore tests; `883dfd637` and `5e514ff4b` join
  package-info paragraphs; `4f8f5039f` takes main's session-initializer refactor and merges
  imports; `a113a3991` keeps the integration POMs, `ServerEventNotifier`, and
  `FileBasedTrustListManager`, adds the fsync from `529d85f9d`, and drops a test integration had
  removed; `93ab6a778` keeps shaded-jar manifest generation and drops the `sun.security`
  optional import. The other merges have empty remerge diffs. `f2024e659` and `952b61f9b` repeat
  earlier merge trees and remain rows only for reachability accounting.
- Intermediate client certificate-manager/group-ID configuration is replaced by the final
  single-group/identity API. `DefaultApplicationGroup`'s temporary lifecycle/deprecation
  changes are superseded by its deletion. The guide shows v1.1.7 constructors, which are
  unchanged from v1.1.6, and final `DefaultCertificateGroup`, not the intermediate APIs.
- Revocation: `9ca6ae468` and `6a5ed08c8` are superseded by `156ff7bb3`, which removes the
  reflective checker and its fallback. `384882e5f` is superseded by `991743079`. The guide's
  comparison describes v1.1.7's actual fallback: without `--add-opens`, `REVOCATION` ran the
  JDK default hard-fail checker and no flag meant no revocation checking.
- `35f0aa0be` narrows the same-key-family token rule from `e164dca70` to username and
  issued-token secrets. `aad3b616b` restores v1.1.7's leaf-only legacy ActivateSession signature
  after `e164dca70` had changed it, so it has no net effect against the baseline. `1265de731`
  refines the UInt64 conversion `7b4616476` that shipped in v1.1.7.
- Condition attach/adopt, custom instances, and application-driven limit states refine a
  runtime absent from v1.1.7. They are consolidated into the shipped capability and its
  limitations, rather than invented migrations from a released Condition runtime.
- Commits on main after v1.1.7 (the 1.1.8-SNAPSHOT line) are `7205956d0`, `2db848479`,
  `0b3eb874f`, `08d2ca6b7`, `f1704586e`, `df2295c6a`, and `9111dd1b9`. None of them needs a guide
  entry. When 1.1.8 is released, move the baseline to it.

## Unresolved questions and review limits

There are no unaccounted commits. The following deployment questions remain outside the
evidence established by these passes:

- Enhanced-policy interoperability and provider behavior with each target peer/runtime were
  not exercised. Source/tests establish supported paths, not external certification.
- The v1.1.7 revocation fallback behavior is established by reading source, not by a test run
  against a 1.1.7 build.
- JSON and XML wire changes were checked against source and tests, not against third-party
  stacks or JSON persisted by 1.1.x applications.
- Real GDS products, older optional-method behavior, and persistent enrollment recovery were
  not exercised. Generated GDS constants were not revalidated against an external NodeSet.
- Filesystem symlink watching, cross-process writers, trust persistence failures, and reconnect
  or certificate-rotation timing need deployment tests.
- Existing supporting docs are not all current. The `ValidationCheck.VALIDITY` Javadoc still
  says an expired CA-issued certificate fails path construction with `Bad_CertificateTimeInvalid`;
  since `991743079` it reports `Bad_SecurityChecksFailed`. The guide follows final source.

For an incremental review, first pin the next tip and confirm this tip remains its ancestor.
Enumerate `43c6f21a2bd2cd8b259b25709f4fa921cd921c68..<new-tip>` without `--first-parent`.
Inspect new parent/merge-resolution diffs, append rows, and reconcile affected guide entries
against v1.1.7 and the new final tree. Update both reviewed-tip fields, coverage, date, samples,
and verification. If history was rewritten, compare reachability sets and redo supersession
accounting instead of assuming an append-only range.

When a new 1.1.x release appears, move the baseline to it. Remove guide content and audit rows
for commits that become its ancestors, check for ported equivalents, and recheck every
"1.1.x behavior" comparison against the new release.
